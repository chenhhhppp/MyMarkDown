# 一、JDBC（8 题）

### 1. JDBC 完整使用步骤？
💡 加载驱动 → DriverManager 获取 Connection → 创建 Statement/PreparedStatement → 执行 SQL → 处理 ResultSet → 关闭资源（try-with-resources 自动关闭）。

### 2. Statement 和 PreparedStatement 区别？⭐⭐⭐
💡 PreparedStatement **预编译**：占位符 ? 传参防 SQL 注入，相同 SQL 不同参数可复用执行计划，性能更好。

### 3. 为什么要用数据库连接池？
💡 建立连接昂贵（TCP 三握手 + 认证 + 会话），池化**创建后复用**；核心参数：初始、最大、最小空闲、获取超时、存活检测。主流：HikariCP（Boot 默认）、Druid。

### 4. HikariCP 为什么是默认且最快？
💡 自定义 FastList（免范围检查）、ConcurrentBag 无锁借还连接、字节码级优化（javassist 生成代理）、代理对象极度精简减少调用开销。

### 5. JDBC 里怎么操作事务？
💡 `conn.setAutoCommit(false)` → 执行 SQL → `conn.commit()` / 异常 `conn.rollback()`；隔离级别 `setTransactionIsolation()`。

### 6. executeQuery / executeUpdate / execute 区别？
💡 查询返回 ResultSet / 增删改返回影响行数 / 万能方法返回 boolean（true 表示有结果集）。

### 7. JDBC 批量插入怎么做才真·批量？
💡 `addBatch()` + `executeBatch()`，且 URL 加 `rewriteBatchedStatements=true`（MySQL 驱动才会把多条 insert 合并重写为一条多 values 的 SQL，性能差几十倍的区别）。

### 8. Druid 和 HikariCP 怎么选？
💡 追极致性能选 HikariCP；要 **SQL 监控、慢日志、防注入防火墙**选 Druid（国内金融/传统企业偏爱）。

# 二、JavaWeb（8 题）

### 9. Servlet 的生命周期？⭐⭐⭐
💡 `init()` 只执行一次（加载时）→ 每个请求走 `service()`（分发 doGet/doPost）→ 容器关闭 `destroy()`。

### 10. Servlet 是单例吗？线程安全吗？⭐⭐
💡 **默认单例多线程**（一个实例并发处理多请求），成员变量共享→不安全；解决：设计成无状态，或用 ThreadLocal 存状态。

### 11. Filter 和 Listener 的区别？
💡 Filter **拦截请求/响应**（链式，做编码、鉴权、日志、跨域）；Listener **监听容器/域对象事件**（启动初始化配置、销毁清理资源）。

### 12. Cookie 和 Session 的区别？⭐⭐⭐
💡 Cookie 存**客户端**（约 4KB，可伪造）；Session 存**服务端**（靠 Cookie 里的 JSESSIONID 关联，也可 URL 重写兜底）。

### 13. 分布式下 Session 怎么共享？⭐⭐
💡 三方案：Redis 集中存储（spring-session，主流）；网关粘性会话（IP/hash 绑定机器）；改用 JWT 无状态令牌（扩容最爽但难主动注销）。

### 14. 转发和重定向的区别？⭐⭐
💡 forward **服务器内部**跳转：一次请求、request 域数据共享、地址栏不变；redirect：两次请求、302、地址栏变、域数据不共享、可跨域。

### 15. GET 和 POST 的本质区别？
💡 本质是**语义**：GET 获取（幂等、可缓存、参数在 URL 明文有长度限制）；POST 提交（非幂等、参数在 body、支持二进制）。注意：POST 也不加密，安全靠 HTTPS。

### 16. Servlet 3.0 异步处理解决什么问题？
💡 `AsyncContext.start()` 把耗时操作交给业务线程池，**立即释放容器线程**（Tomcat 工作线程宝贵），适合长耗时任务 + 完成后主动推响应——是 SSE 的基础。

# 三、Java 多版本特性（6 题）

### 17. JDK8 核心新特性？⭐⭐⭐
💡 Lambda、Stream API、Optional、接口 default/static 方法、新时间 API（LocalDateTime）、元空间替代永久代。

### 18. JDK9~11 主要变化？
💡 9 模块化（JPMS）；10 `var` 局部变量推断；11 LTS：标准化 HttpClient、String 增强（isBlank/strip/repeat/lines）、集合增强（var、of）。

### 19. JDK17（LTS）核心特性？⭐⭐
💡 record 正式（16）、sealed 密封类正式（17）、instanceof 模式匹配（16）、文本块（15）、强封装 JDK 内部 API；**SpringBoot3 的最低门槛**。

### 20. JDK21（LTS）核心特性？⭐⭐⭐（2026 面试新宠）
💡 **虚拟线程正式**（JEP 444）、分代 ZGC（JEP 439）、record 模式匹配、switch 模式匹配正式、结构化并发+作用域值（预览）。

### 21. record 是什么？适合什么场景？
💡 不可变数据载体：自动生成全参构造、访问器、equals/hashCode/toString；字段 final 不可改。适合 DTO/VO/值对象，**不适合实体类**（要可变）。

### 22. var 的限制？
💡 只能**局部变量**（需初始化、不能 null、不能数组初始化简写）；不能用于字段、方法参数、返回值。

# 四、Maven（5 题）

### 23. dependency 的 scope 有哪些？⭐⭐
💡 compile（默认全阶段）、test（仅测试）、provided（编译期要，打包不带，如 Lombok/servlet-api）、runtime（运行时要，如 JDBC 驱动）、import（只在 dependencyManagement 引 BOM）、system（基本不用）。

### 24. 依赖冲突怎么排查和解决？⭐⭐⭐
💡 Maven 调解规则：**最短路径优先，同长先声明优先**。排查：`mvn dependency:tree -Dverbose`；解决：`<exclusions>` 排除传递依赖，或 dependencyManagement 锁版本。

### 25. Maven 三大生命周期和常用命令？
💡 clean（清理）→ default（构建：compile → test → package → install → deploy）→ site（站点文档）。命令按序自动执行前置阶段。

### 26. dependencyManagement 和 dependencies 区别？⭐⭐
💡 前者只是**声明版本号，不实际引入**（父 POM 统一管版本，子模块引时不用写 version）；后者真实引入依赖。

### 27. 聚合和继承的区别？
💡 聚合（modules）：父聚合子模块**一起构建**；继承（parent）：子复用父的**配置和依赖**；实际项目通常一个 POM 同时干这两件事。

# 五、MyBatis（10 题）

### 28. MyBatis 的执行流程？⭐⭐⭐
💡 解析配置 → SqlSessionFactory → 开 SqlSession → getMapper 拿**动态代理对象** → MapperMethod → Executor 执行 → StatementHandler 组装 JDBC → ResultSetHandler 映射结果。

### 29. Mapper 接口没有实现类，为什么能执行 SQL？⭐⭐⭐
💡 JDK **动态代理**：MapperProxy 拦截接口方法调用，用 **namespace + 方法名**定位到 XML（或注解）里的 Statement，转成 SqlSession 的增删改查。

### 30. `#{}` 和 `${}` 的区别？⭐⭐⭐
💡 `#{}` 预编译为 `?` 占位符，**防注入**（值传参首选）；`${}` 字符串直接**拼接**，仅用于动态表名/列名/order by 等**结构位置**，且必须白名单校验。

### 31. 一级缓存和二级缓存？⭐⭐⭐
💡 一级：**SqlSession 级别**，默认开启，同一 session 相同查询直接命中；二级：**namespace 级别**，需手动开启（跨 session 共享）。分布式下二级缓存易脏读，生产多用 Redis 替代。

### 32. 一级缓存什么时候失效？
💡 SqlSession 关闭/commit/rollback，或执行了 insert/update/delete（刷新缓存），或 `localCacheScope=STATEMENT` 配置。

### 33. 延迟加载的原理？
💡 关联对象先不查，**真正调用 getter 时**才发第二次 SQL；实现靠动态代理（cglib/javassist）拦截 getter；`lazyLoadingEnabled=true` 开启，`aggressiveLazyLoading=false` 按需加载。

### 34. 动态 SQL 常用标签？
💡 `<if>` 条件、`<where>` 智能去 AND、`<set>` 智能去逗号、`<choose>/<when>/<otherwise>` 多选一、`<foreach>` 遍历集合（in 查询）、`<trim>` 自定义前后缀。

### 35. Mapper 接口方法能重载吗？⭐⭐
💡 **不能**。Statement 的唯一标识是 `namespace + 方法名`，与参数无关，重载的两个方法 id 相同直接冲突（启动报错）。

### 36. MyBatis 插件（拦截器）原理？⭐⭐
💡 责任链 + **动态代理**，只能拦截四大对象：**Executor / StatementHandler / ParameterHandler / ResultSetHandler**；分页插件 PageHelper 就是拦截 StatementHandler 改写 SQL 加 LIMIT。

### 37. 分页怎么做？物理分页和内存分页区别？
💡 物理分页：SQL 层 LIMIT（PageHelper 拦截改写 / MP 分页插件），只取一页数据✅；内存分页：RowBounds 把结果全查回来再截取，数据量大直接 OOM❌。

# 六、MyBatis-Plus（6 题）

### 38. MyBatis-Plus 和 MyBatis 的关系？
💡 "**只做增强，不做改变**"：完全兼容原生 MyBatis；额外提供 BaseMapper/IService **通用 CRUD 零 XML**、条件构造器、代码生成器、分页/乐观锁等插件。

### 39. QueryWrapper 和 LambdaQueryWrapper 怎么选？
💡 优先 **Lambda 版**：`User::getName` 方法引用替代字符串列名，**编译期检查**，改字段名编译直接报错；QueryWrapper 写错列名运行时才发现。

### 40. MP 常用注解有哪些？
💡 `@TableName`（表名）、`@TableId(type = IdType.ASSIGN_ID)`（主键雪花 ID）、`@TableField`（字段映射/`exist=false` 非表字段）、`@TableLogic`（逻辑删除）。

### 41. 逻辑删除怎么实现？⭐⭐
💡 `@TableLogic` 标注 deleted 字段 + 全局配置 logic-delete-value；之后 MP 的 delete 变 `UPDATE SET deleted=1`，**所有查询自动拼 `deleted=0`**，业务代码零改动。

### 42. MP 分页插件怎么配置？
💡 注册 `MybatisPlusInterceptor` 并加 `PaginationInnerInterceptor(DbType.MYSQL)`；没有这个拦截器，`selectPage` 只查全部不截断（经典坑）。

### 43. MP 怎么实现乐观锁？
💡 字段标 `@Version` + 注册 `OptimisticLockerInnerInterceptor`；更新时自动 `SET version=version+1 WHERE version=旧值`，影响行数为 0 说明被并发修改，重试或报错。

# 七、Spring 源码级（10 题）⭐⭐⭐

### 44. refresh() 的核心流程？
💡 12 步重点记 4 步：`obtainFreshBeanFactory`（BeanFactory）→ `invokeBeanFactoryPostProcessors`（**扫描解析 BeanDefinition**，ConfigurationClassPostProcessor 在这）→ `registerBeanPostProcessors` → `finishBeanFactoryInitialization`（**实例化所有非懒加载单例**）。

### 45. BeanDefinition 是什么？
💡 Bean 的"**图纸**"：class、scope、lazy、initMethod、依赖等元信息；来源：组件扫描、@Bean、@Import、XML。改图纸就改了 Bean 的生产方式。

### 46. BeanFactoryPostProcessor 和 BeanPostProcessor 区别？⭐⭐⭐
💡 前者作用于 **BeanDefinition（图纸）**，在 Bean 实例化**前**（如占位符解析 ${}）；后者作用于 **Bean 实例**，在初始化**前后**（AOP 代理就在这生成）。

### 47. @Autowired 的注入原理？
💡 `AutowiredAnnotationBeanPostProcessor` 在属性填充阶段：反射找注入点 → 按**类型**收集候选 → @Qualifier/字段名筛选 → 多候选报错（配 @Primary/@Qualifier 解决）。

### 48. Spring 事件机制的原理？
💡 `ApplicationEventMulticaster`（事件广播器）按事件类型找到所有匹配的 `ApplicationListener`，**默认同步**逐个回调；@Async 才异步。

### 49. getBean 遇到 FactoryBean 怎么处理？
💡 从单例池拿到 FactoryBean 后自动调 `getObject()` 返回**产品**；beanName 加 `&` 前缀才返回工厂本身；产品默认也会缓存，`isSingleton()` 控制。

### 50. 为什么构造器注入的循环依赖无解？⭐⭐
💡 三级缓存暴露的是"**实例化后、属性填充前**"的早期引用；构造器注入发生在**实例化阶段本身**，对象还没造出来，没有早期引用可暴露。

### 51. AOP 拦截链怎么执行？
💡 `ReflectiveMethodInvocation.proceed()` **递归推进责任链**：@Around → @Before → 目标方法 → @AfterReturning/@After（finally）→ 逐层返回给 @Around 的后续逻辑。

### 52. Spring 有哪些扩展点（考察体系认知）？
💡 BeanFactoryPostProcessor（改图纸）、BeanPostProcessor（改实例）、@PostConstruct/InitializingBean（初始化回调）、@Import/@EnableXxx（注册组件）、ApplicationListener（事件）、SmartInitializingSingleton（单例就绪后批量处理）。

### 53. Spring 是怎么解决配置类解析的？@Configuration 里 @Bean 方法互调为什么不新建对象？
💡 CGLIB 增强 Configuration 类：`@Bean` 方法互调被拦截为**先查容器单例**，保证 Bean 唯一；@Component 里的 @Bean 互调就是普通方法调用（会 new 新对象，官方叫 Lite 模式）。

# 八、SpringBoot（8 题）

### 54. SpringBoot 的启动流程？⭐⭐⭐
💡 `SpringApplication.run`：推断应用类型 → 准备 Environment（加载配置）→ **创建 ApplicationContext** → prepareContext（注册启动类）→ **refresh（自动装配 + 实例化单例发生在这）** → 回调 Runner（CommandLineRunner/ApplicationRunner）。

### 55. 配置文件的优先级？⭐⭐
💡 核心规则：**外置 > 内置、profile > 默认、命令行参数最高**。命令行参数 > 系统环境变量 > application-{profile}.yml > application.yml；同名下 properties 优先于 yml。

### 56. 自定义 Starter 的步骤？⭐⭐⭐
💡 ① 写自动配置类（@AutoConfiguration + @ConditionalOnXxx + @EnableConfigurationProperties）② 在 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 登记全类名 ③ 建空 starter 模块只依赖 autoconfigure 模块，使用方引 starter 即自动生效。

### 57. @ConfigurationProperties 和 @Value 区别？
💡 前者：**批量绑定**、宽松绑定（驼峰/下划线随意）、支持校验（@Validated）、支持配置中心刷新（@RefreshScope）；后者：单字段 + SpEL，不能批量刷新。

### 58. 内嵌 Tomcat 是怎么启动的？
💡 ServletWebServerApplicationContext 在 `onRefresh` 阶段通过 **ServletWebServerFactory 创建并启动 Tomcat**，把 DispatcherServlet 注册进去；打包成可执行 fat jar，`java -jar` 直接跑，无需外部容器。

### 59. 启动时执行初始化逻辑有哪些方式？
💡 @PostConstruct（Bean 级最早）→ InitializingBean → CommandLineRunner / ApplicationRunner（容器就绪后，能拿 args）→ ApplicationListener<ApplicationReadyEvent>。

### 60. 配置中心是怎么实现动态刷新的？
💡 Nacos 长轮询监听变更 → 触发 `RefreshEvent` → ContextRefresher 重建 Environment → **销毁并重建 @RefreshScope 的 Bean**（普通 singleton 不刷新，这就是要标 @RefreshScope 的原因）。

### 61. Actuator 是干嘛的？
💡 生产级监控端点：/health（存活探针）、/metrics（指标，对接 Prometheus）、/env、/info；K8s 的 liveness/readiness 探针直接打 /health 路径。

# 九、SpringMVC（6 题）

### 62. 参数是怎么绑定到 Controller 方法的？
💡 `HandlerMethodArgumentResolver` 策略接口按参数注解/类型逐个解析：@RequestParam、@PathVariable、@RequestBody、HttpServletRequest、自定义对象（反射设值）。

### 63. @RequestBody 的原理？
💡 根据请求 **Content-Type** 选择 HttpMessageConverter（application/json → Jackson/MappingJackson2HttpMessageConverter），把输入流反序列化成对象——所以 body 是流，**一个请求只能读一次**。

### 64. 拦截器和 Filter 的区别？⭐⭐
💡 拦截器是 **Spring 生态**（能拿 HandlerMethod、Bean 注入），三阶段 pre/post/afterCompletion；Filter 是 **Servlet 规范**，在 DispatcherServlet 之前就介入（更早），适合与业务无关的通用处理（编码、CORS）。

### 65. 多个拦截器的执行顺序？
💡 **preHandle 正序（注册顺序），postHandle 和 afterCompletion 反序**（栈结构，最先进的最后出）；preHandle 返回 false 后续全断，已执行的 afterCompletion 仍会跑。

### 66. 全局异常处理的原理？
💡 @RestControllerAdvice + @ExceptionHandler 的方法被 `ExceptionHandlerExceptionResolver` 收集建表；抛异常时按**异常类型最精确匹配**找到处理方法，返回值走正常消息转换。

### 67. RESTful 接口怎么设计？
💡 资源用名词复数（/users/1）、动作用 HTTP 方法（GET 查/POST 增/PUT 全量改/PATCH 部分改/DELETE 删）、语义化状态码（200/201/400/401/404/500）；版本放路径 /v1/。

# 十、SpringWebFlux（8 题）

### 68. WebFlux 和 SpringMVC 的区别？⭐⭐⭐
💡 三连：**编程模型**（声明式 Mono/Flux vs 命令式阻塞）；**运行容器**（Netty 事件循环 vs Tomcat 线程池）；**并发模型**（少量线程非阻塞处理海量 IO vs 一请求一线程）。

### 69. Mono 和 Flux 是什么？
💡 Reactor 的两个发布者：**Mono 0~1 个元素**（查单个用户、LLM 单条回复）、**Flux 0~N 个**（列表、SSE 流）。都是异步序列，代表"未来的数据"。

### 70. Reactor 的两个阶段？（经典坑）
💡 **组装期**：链式调用只是描述了流水线，**什么都没执行**；**订阅期**：`subscribe()` 被调用才真正触发。没有订阅者的 Mono 就是张图纸——忘订阅=白写。

### 71. map 和 flatMap 的区别？
💡 map：**同步**转换，一对一（对象→对象）；flatMap：**异步**转换，一对多/需要返回 Mono|Flux 时用（如调外部接口），**无序**；concatMap 保序，flatMapSequential 保序并发。

### 72. 背压（Backpressure）是什么？⭐⭐
💡 订阅者通过 `request(n)` 告知发布者"我还能消费几个"，**由消费者控制流速**，防止快生产压垮慢消费；应对策略：onBackpressureBuffer（缓冲）/ Drop（丢）/ Latest（留最新）。

### 73. 什么场景选 WebFlux？⭐⭐⭐
💡 **IO 密集 + 高并发长连接**：SSE 流式输出（LLM 场景标配）、消息推送、网关聚合多接口；**不适合**：CPU 密集型（吃不满事件循环优势）、团队不熟响应式（维护成本高）、代码里有大量阻塞调用。

### 74. WebFlux 里怎么调用阻塞代码（JDBC）？
💡 包成 `Mono.fromCallable(() -> jdbcCall()).subscribeOn(Schedulers.boundedElastic())`，把阻塞**弹到弹性线程池**执行；直接在事件循环线程里阻塞 = 卡死整个 Netty EventLoop，全部请求陪葬。

### 75. WebFlux 怎么实现 SSE 流式接口？
💡 返回 `Flux<ServerSentEvent<String>>` + `produces = MediaType.TEXT_EVENT_STREAM_VALUE`，每个元素自动按 `data:` 帧推送——**大模型流式输出的标准姿势**（对接 Flux<ChatResponse> 逐 token 转发）。
