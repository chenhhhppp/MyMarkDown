# 🔀 Part A：易混概念对照大全（35 组高频双胞胎）

> 💡 用法：**只看左边栏目回忆右边**，卡壳的标 ⚠️ 当天复盘。

## A1 Java 基础篇（7 组）

### A1.1 String vs StringBuilder vs StringBuffer

| 对比   | String   | StringBuilder | StringBuffer        |
| ---- | -------- | ------------- | ------------------- |
| 可变性  | ❌ 不可变    | ✅ 可变          | ✅ 可变                |
| 线程安全 | ✅（因为不可变） | ❌             | ✅（方法全 synchronized） |
| 场景   | 常量、少量拼接  | 单线程拼接（99% 场景） | 多线程拼接（几乎绝迹）         |

- 🎵 **记忆点**：**「String 死心眼，Builder 单干快，Buffer 带锁慢」**

### A1.2 == vs equals vs hashCode

| 符号/方法    | 比什么         | 说明                               |
| -------- | ----------- | -------------------------------- |
| ==       | 地址（是不是同一个）  | 基本类型比值                           |
| equals   | 内容（长得像不像）   | 可重写                              |
| hashCode | 散列定位（储物柜编号） | **约定：equals 相等 → hashCode 必须相等** |

- 🎵 **记忆点**：**「==比地址，equals比内容，相等对象哈希必等」**

### A1.3 重载 vs 重写

| 对比 | 重载 Overload | 重写 Override |
| -- | ----------- | ----------- |
| 位置 | 同一个类        | 父子类         |
| 参数 | 必须不同        | 必须相同        |
| 绑定 | 编译期（静态）     | 运行期（动态多态）   |

- 🎵 **记忆点**：**「重载横向堆方法，重写纵向盖父类」**

### A1.4 接口 vs 抽象类

| 对比    | 接口                     | 抽象类         |
| ----- | ---------------------- | ----------- |
| 关系语义  | can-do（技能）             | is-a（亲爹）    |
| 数量    | 实现多个                   | 只继承一个       |
| 成员变量  | 默认 public static final | 可有状态、可有无参构造 |
| JDK8+ | 可有 default/static 方法   | —           |

- 🎵 **记忆点**：**「抽象类是爹（单继承），接口是技能（多佩戴）」**

### A1.5 浅拷贝 vs 深拷贝

| 对比             | 浅拷贝         | 深拷贝       |
| -------------- | ----------- | --------- |
| 引用字段           | 只复制引用（共用对象） | 递归复制出全新对象 |
| Object.clone() | ✅ 默认浅拷贝     | 需自己实现递归克隆 |

- 🎵 **记忆点**：**「浅拷共用一间房，深拷各住各的家」**

### A1.6 final vs finally vs finalize

| 关键字      | 用途                       | 备注                  |
| -------- | ------------------------ | ------------------- |
| final    | 修饰符：类不能继承/方法不能重写/变量不能重赋值 | 引用不能改，指向的对象内容可改     |
| finally  | try-catch 的兜底块           | 一定执行（除 System.exit） |
| finalize | 对象回收前回调                  | **已废弃**，知道即可        |

- 🎵 **记忆点**：**「final 锁、finally 兜、finalize 已退休」**

### A1.7 Integer 缓存陷阱

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;
a == b;  // true  （-128~127 走缓存池，同一个对象）
c == d;  // false （128 超缓存，各自 new）
```

- 🎵 **记忆点**：**「-128 到 127 有缓存，出了这个门 == 就翻脸」**

## A2 并发篇（6 组）

### A2.1 sleep vs wait（万年必考）

| 对比  | sleep    | wait               |
| --- | -------- | ------------------ |
| 属于  | Thread 类 | Object 类           |
| 释放锁 | ❌ 抱着锁睡   | ✅ 释放锁              |
| 前提  | 随时可用     | 必须在 synchronized 内 |
| 唤醒  | 时间到自动醒   | notify/notifyAll   |

- 🎵 **记忆点**：**「sleep 抱锁睡（自私），wait 放锁等（大方）」**

### A2.2 synchronized vs Lock（ReentrantLock）

| 对比  | synchronized | Lock                  |
| --- | ------------ | --------------------- |
| 层面  | JVM 关键字      | JDK 类库                |
| 释放  | 异常自动释放       | 必须手动 unlock（finally！） |
| 灵活性 | 非公平、不可中断     | 公平锁、可中断、tryLock 超时    |
| 功能  | 互斥           | + Condition 多条件队列     |

- 🎵 **记忆点**：**「synchronized 省心自动挡，Lock 手动挡功能全」**

### A2.3 volatile vs synchronized

| 对比  | volatile | synchronized |
| --- | -------- | ------------ |
| 可见性 | ✅        | ✅            |
| 有序性 | ✅（禁重排）   | ✅            |
| 原子性 | ❌        | ✅            |
| 阻塞  | 不阻塞      | 可能阻塞         |

- 🎵 **记忆点**：**「volatile 是广播（通知全员），synchronized 是门禁（一次一人）」**

### A2.4 CountDownLatch vs CyclicBarrier

| 对比 | CountDownLatch | CyclicBarrier  |
| -- | -------------- | -------------- |
| 语义 | 倒计时：等 N 件事做完   | 集合：等 N 个人到齐    |
| 复用 | 一次性            | 可 reset 循环用    |
| 场景 | 主线程等所有子任务      | 多线程互相等（分段任务汇总） |

- 🎵 **记忆点**：**「Latch 倒计时一次完，Barrier 人齐了再一起走」**

### A2.5 Runnable vs Callable

| 对比  | Runnable     | Callable         |
| --- | ------------ | ---------------- |
| 返回值 | ❌ void       | ✅ 泛型返回（配 Future） |
| 异常  | 只能 try-catch | 可抛受检异常           |

### A2.6 悲观锁 vs 乐观锁

| 对比 | 悲观锁                              | 乐观锁        |
| -- | -------------------------------- | ---------- |
| 思想 | 先锁再操作                            | 不锁，提交时校验冲突 |
| 实现 | synchronized / select for update | CAS / 版本号  |
| 场景 | 写多冲突频繁                           | 读多冲突少      |

- 🎵 **记忆点**：**「悲观先占座，乐观凭票上车」**

## A3 Spring 篇（5 组）

### A3.1 JDK 动态代理 vs CGLIB

| 对比        | JDK 代理    | CGLIB                     |
| --------- | --------- | ------------------------- |
| 原理        | 实现接口 + 反射 | 继承目标类，子类字节码增强             |
| 要求        | 目标必须有接口   | 类和方法不能是 final             |
| Spring 默认 | 有接口用它     | 无接口用 CGLIB（Boot 默认 CGLIB） |

- 🎵 **记忆点**：**「JDK 靠接口，CGLIB 靠继承」**

### A3.2 BeanFactory vs FactoryBean（刚考过！）

| 对比 | BeanFactory             | FactoryBean                                  |
| -- | ----------------------- | -------------------------------------------- |
| 身份 | IoC **容器**顶层接口          | 一个**特殊的 Bean**                               |
| 职责 | 管理所有 Bean               | `getObject()` 决定注册什么对象                       |
| 举例 | ApplicationContext 是它儿子 | SqlSessionFactoryBean、FeignClientFactoryBean |

- 🎵 **记忆点**：**「Factory 结尾的是 Bean，Bean 开头的是容器——名字反着记！」**

### A3.3 @Autowired vs @Resource

| 对比   | @Autowired              | @Resource                |
| ---- | ----------------------- | ------------------------ |
| 出处   | Spring                  | JDK（JSR-250）             |
| 注入方式 | **先 byType**，多个再 byName | **先 byName**，找不到再 byType |
| 配套   | @Qualifier 指定名字         | name 属性直接指定              |

### A3.4 @Component vs @Bean

| 对比 | @Component | @Bean                    |
| -- | ---------- | ------------------------ |
| 位置 | 类上         | 方法上（通常 @Configuration 里） |
| 场景 | 自己写的类      | **第三方 jar 的类**（改不了源码）    |

- 🎵 **记忆点**：**「自己的类扫 @Component，别人的类 @Bean 手工装」**

### A3.5 IOC vs DI

- 🗣️ **一句话**：IOC 是**思想**（对象的控制权反转给容器），DI（依赖注入）是**实现手段**（setter/构造器把依赖塞进来）。
- 🎵 **记忆点**：**「IOC 是理念，DI 是打法」**

## A4 MySQL 篇（6 组）

### A4.1 redo log vs undo log vs binlog ⭐⭐⭐

| 对比 | redo log      | undo log      | binlog          |
| -- | ------------- | ------------- | --------------- |
| 层级 | InnoDB 引擎     | InnoDB 引擎     | Server 层（所有引擎）  |

### A4.2 聚簇索引 vs 二级索引

- 🎵 复习口诀：**「主键带全行，辅助存主键，查完要回表」**（详见第二册 6.2）

### A4.4 delete vs truncate vs drop

- 🎵 **记忆点**：**「delete 慢能悔，truncate 快清场，drop 连房拆」**

## B1 新趋势押题（15 题，别人还没复习到！）⭐⭐⭐

### B1.1 虚拟线程连环 5 问

**① 虚拟线程和平台线程的区别？**

> 🗣️ 平台线程 1:1 映射 OS 内核线程（MB 级栈、创建贵），虚拟线程由 JVM 调度、挂在载体线程上（KB 级、可创建百万个），阻塞时自动 unmount 让出载体。

**② 什么场景用虚拟线程？**

> 🎵 **口诀「IO 密集用虚拟，CPU 密集用平台」**——大量阻塞等待（HTTP 调用、DB 查询）收益最大。

**③ 怎么用？**

```java
// JDK21 正式
Thread.startVirtualThread(() -> callApi());
// 或线程池风格（每任务一个虚拟线程）
Executors.newVirtualThreadPerTaskExecutor();
// SpringBoot: spring.threads.virtual.enabled=true 一键开启 Tomcat 虚拟线程
```

**④ 虚拟线程会替代线程池吗？**

> 不会完全替代：虚拟线程**便宜到不需要池化**（池的存在就是为了省线程），但 CPU 密集任务仍需要池限流保护核数；另外 `synchronized` 长阻塞会 pin 住载体线程（JDK24 已优化）。

**⑤ 虚拟线程的坑？**

> pin 问题（synchronized/ native 方法）、ThreadLocal 滥用（百万线程=百万份副本，慎用）、不要池化虚拟线程。

### B1.2 HTTP/3 与 QUIC

> 🗣️ HTTP/3 底层从 TCP 换成 **QUIC（基于 UDP）**：0-RTT 建连、流之间独立不互相阻塞（根治 TCP 队头阻塞）、连接迁移（切 WiFi 不断线）。
> 🎵 **口诀「换道 UDP，握手零往返，队头阻塞连根拔」**

### B1.3 GraalVM Native Image

> 🗣️ AOT 编译成本地机器码：**毫秒级启动、内存省一半**，适合 Serverless/CLI；代价是构建慢、反射/动态代理要提前配置、峰值性能可能不如 JIT。
> 🎵 **口诀「启动飞快内存省，动态特性要报备」**——SpringBoot 3 的 AOT 就是为此而生。

### B1.4 SpringBoot 3.x / Spring 6 必知变化

| 变化           | 说明                                        |
| ------------ | ----------------------------------------- |
| Jakarta 命名空间 | javax.\* → jakarta.\*（必须 JDK17+）          |
| AOT + Native | 支持 GraalVM 原生镜像                           |
| 虚拟线程         | `spring.threads.virtual.enabled=true`     |
| 可观测性         | Micrometer Tracing 取代 Spring Cloud Sleuth |

### B1.5 云原生时代的 Java 后端素养

> 🎵 **口诀「探针、优雅停机、配置外置、无状态」**——K8s 健康检查三件套（liveness/readiness/startup）、SIGTERM 优雅下线（先摘流量再停）、12-Factor 配置环境变量化、实例无状态才能随便扩缩。

### B1.6 AI 应用工程化 5 连问

**① RAG 效果差，你怎么优化？**

> 分层排查口诀「**切块、检索、重排、生成**」四层：切块策略（固定→语义分块）、检索（向量→**混合检索 BM25+向量**）、加 **Rerank 重排**提升相关性、生成端 Prompt 加引用溯源 + 温度调低，最后建**评估集**量化迭代。

**② Agent 落地最大的坑？**

> 🎵 **口诀「幻觉、工具误调、成本、可观测」**——答案加引用兜底幻觉、工具调用参数强校验+重试、缓存+小模型分级降成本、全链路 trace 观测。

**③ Function Calling 和 MCP 什么关系？**

> Function Calling 是模型「选工具给参数」的能力；MCP 是工具接入的**标准协议**（AI 的 USB 口）——前者是脑子，后者是插座。

**④ 大模型会取代后端吗？**

> 「AI 增强开发是真，取代后端是假——**业务系统、数据一致性、高并发这些脏活累活反而更需要工程化人才**，而 AI 应用的落地（RAG/Agent/成本控制）恰恰是后端的新战场。」（→ 用第三册 12.5 话术展开）

**⑤ 上下文工程是什么？**

> Prompt 工程管「怎么问」，**上下文工程管「往上下文里塞什么」**——系统指令、RAG 片段、历史摘要、工具结果的裁剪与编排，是 Agent 效果的核心杠杆。

## B2 跨模块组合拳（10 题，串联能力考的就是这个）

### B2.1 一个 HTTP 请求在 SpringMVC 里的完整旅程 ⭐⭐⭐

> 🎵 **答题骨架**（30 秒版）：
> 「请求进 Tomcat 线程 → **DispatcherServlet** 总调度 → **HandlerMapping** 找到对应 Controller → **HandlerAdapter** 执行（中途路过拦截器 preHandle）→ **@ControllerAdvice 全局异常**和参数解析绑定 → Controller → Service 层 **AOP 事务代理**开启事务 → MyBatis 拿 **连接池连接**执行 SQL → 返回结果一路回传 → 事务提交 → JSON 序列化响应。」

### B2.2 从点击「下单」到扣库存的全链路

> 「前端 → 网关（鉴权/限流）→ 防重（幂等号）→ Redis Lua 预扣库存 → 发 RocketMQ（事务消息）→ 订单消费者落库（乐观锁兜底）→ 延迟消息 30 分钟未支付自动取消回补库存 → 推送结果。」

### B2.3 一条 SQL 从执行到落盘的路径

> 「Server 层：连接器 →（缓存）→ 分析器 → 优化器（选索引）→ 执行器；InnoDB 层：缓冲池找页（没有从磁盘读）→ 写 undo log（回滚准备）→ 改缓冲池 → 写 redo log（prepare）→ 写 binlog → redo log commit（**两阶段提交**保证 redo/binlog 一致）→ 后台线程异步刷脏页。」

### B2.4 缓存 + DB + MQ 在一个接口里怎么协作？

> 「读：先 Redis，miss 查 DB 回填（防穿透：空值+布隆）；写：先 DB 再删缓存，发 MQ 通知下游；热点数据加本地二级缓存；失败场景靠补偿任务对账。」

### B2.5 服务雪崩的完整防护体系

> 「入口限流（令牌桶）→ 资源隔离（线程池/信号量舱壁）→ 熔断（错误率跳闸，半开试探）→ 降级（兜底数据）→ 超时重试（幂等前提）层层设防。」
> 🎵 **口诀「限、隔、熔、降、超」五字诀**
