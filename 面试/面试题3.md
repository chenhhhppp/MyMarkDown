# 一、Java 基础（20 题）

### 1. JDK / JRE / JVM 的关系？
💡 JDK（开发工具包）⊇ JRE（运行环境）⊇ JVM（虚拟机）；JVM 是跨平台的核心，JRE = JVM + 核心类库，JDK = JRE + 编译器 javac 等工具。

### 2. == 和 equals 的区别？⭐⭐⭐
💡 == 比较基本类型**比值**、引用类型**比地址**；equals 默认（Object）也是比地址，但 String/Integer 等**重写后比内容**。

### 3. 为什么重写 equals 必须重写 hashCode？⭐⭐⭐
💡 约定：等价对象必须有相等的 hashCode。HashMap 先用 hash **定位桶**再用 equals 比内容，只重写 equals 会导致等价对象散落到不同桶——**存进去取不出来**。

### 4. String / StringBuilder / StringBuffer 的区别？⭐⭐⭐
💡 String 不可变（每次拼接产生新对象）；StringBuilder 可变**非线程安全**（单线程拼接首选）；StringBuffer 可变 + synchronized **线程安全**（慢）。

### 5. String 为什么设计成不可变？
💡 final 字符数组：①字符串常量池可安全共享 ②天然线程安全 ③hashCode 可缓存（安心当 HashMap 的 key）④防篡改（路径/类名安全）。

### 6. 重载和重写的区别？⭐⭐
💡 重载：**同一个类**里方法同名参数不同，编译期确定；重写：**子类覆盖**父类同签名方法，运行期确定——多态的基础。

### 7. 接口和抽象类的区别？⭐⭐⭐
💡 抽象类是 **is-a**（是什么）：单继承、有构造器、成员任意；接口是 **can-do**（能干什么）：多实现、变量默认 public static final、JDK8 后有 default/static 方法。选型：模板复用用抽象类，定义能力契约用接口。

### 8. 成员内部类和静态内部类的区别？⭐⭐
💡 静态内部类**不持有外部类引用**，创建不需要外部实例（Builder 模式常用）；成员内部类隐式持有 `外部类.this`，可能引起内存泄漏。

### 9. Integer 的 == 陷阱（127 vs 128）？⭐⭐
💡 IntegerCache 缓存 **-128~127**：这个范围 == 为 true（同一缓存对象），超出则 false（新对象）；所以包装类比较**永远用 equals**。

### 10. Java 集合体系总览？
💡 双体系：**Collection**（List 有序可重复 / Set 去重 / Queue 队列）+ **Map**（键值对，独立于 Collection）。

### 11. ArrayList 和 LinkedList 的区别？⭐⭐⭐
💡 ArrayList **动态数组**：随机访问 O(1)，尾部插入均摊 O(1)，扩容 1.5 倍；LinkedList **双向链表**：头尾插删 O(1)，随机访问 O(n)。实际开发 99% 用 ArrayList（CPU 缓存友好）。

### 12. HashMap 的底层原理（JDK8）？⭐⭐⭐
💡 **数组 + 链表 + 红黑树**：hash 定位桶，冲突拉链；链长 ≥8 且数组容量 ≥64 转红黑树（≤6 退化回链表）；默认容量 16、负载因子 0.75，元素超 `容量×0.75` 扩容 2 倍并 rehash。

### 13. HashMap 为什么容量必须是 2 的幂？
💡 `(n-1) & hash` 替代取模运算：n 为 2 的幂时结果等价于 hash%n 但**快得多**，且二进制位全 1 保证**均匀分布**不浪费桶。

### 14. HashMap 线程不安全的表现？ConcurrentHashMap 怎么解决？⭐⭐⭐
💡 1.7 头插法并发扩容**成环死循环**，1.8 尾插法并发 put **数据覆盖丢失**；CHM 1.8：CAS 初始化/空桶插入 + **synchronized 只锁桶头**（锁粒度极细）+ 协助扩容。

### 15. fail-fast 和 fail-safe 的区别？⭐⭐
💡 fail-fast：遍历时 modCount 检测到结构性修改立刻抛 **ConcurrentModificationException**（ArrayList，连 for-each 里 remove 都炸）；fail-safe：遍历副本或弱一致性（CopyOnWriteArrayList、Concurrent 系列），不抛但可能读到旧值。

### 16. Java 异常体系？⭐⭐⭐
💡 Throwable 分两支：**Error**（系统级，不该捕获：OOM/StackOverflowError）+ **Exception**（受检异常：编译器强制处理如 IOException；非受检：RuntimeException 如 NPE/数组越界）。

### 17. try 里 return 了，finally 还执行吗？⭐⭐
💡 **执行**，且在真正返回前执行（返回值已先算好暂存，finally 改基本类型变量不影响结果）；finally 不执行的唯三：System.exit()、JVM 崩溃、线程被杀。

### 18. 反射是什么？有什么用和代价？
💡 运行时动态获取类信息、调用方法/访问字段；**框架的基石**（Spring IOC 反射造 Bean、MyBatis 动态代理）；代价：性能开销 + 破坏封装 + 绕过编译检查。

### 19. 深拷贝和浅拷贝的区别？
💡 浅拷贝：只复制一层，引用字段**共用同一个对象**（Object.clone 默认）；深拷贝：递归复制整个对象图，两边完全独立（序列化/手动递归 clone 实现）。

### 20. BIO / NIO / AIO 的区别？⭐⭐
💡 BIO：一连接一线程，阻塞；NIO：**Channel + Buffer + Selector 多路复用**，一个线程管海量连接（Netty 的根基）；AIO：事件回调（Linux 实现不成熟，实际还是 NIO 为主）。

# 二、JUC 并发编程（15 题）

### 21. 并发三性是什么？分别怎么保证？⭐⭐⭐
💡 **原子性**（synchronized/Lock/CAS）、**可见性**（volatile/synchronized/final）、**有序性**（volatile 禁重排/happens-before 规则）——一切并发问题的根源与解药。

### 22. 创建线程有几种方式？
💡 ①继承 Thread ②实现 Runnable ③Callable + FutureTask（有返回值、可抛异常）④线程池（实际开发唯一正确姿势）⑤JDK21 虚拟线程。

### 23. 线程的六种状态？⭐⭐⭐
💡 NEW → RUNNABLE →（锁竞争失败 BLOCKED）（wait/join 无限期 WAITING）（sleep/带参 wait/join 超时 TIMED_WAITING）→ TERMINATED。

### 24. wait 和 sleep 的区别？⭐⭐⭐
💡 wait 是 **Object** 方法，**释放锁**，必须在 synchronized 中调用，靠 notify 唤醒；sleep 是 **Thread** 方法，**不释放锁**，任意位置可睡。最经典陷阱题！

### 25. synchronized 和 Lock 的区别？⭐⭐⭐
💡 synchronized：JVM 关键字、自动释放、非公平、不可中断；Lock（ReentrantLock）：API 层面、手动 unlock（finally）、支持**公平锁/可中断/tryLock 超时/多个 Condition**。

### 26. synchronized 的锁升级过程？⭐⭐⭐
💡 **无锁 → 偏向锁**（只有一个线程反复拿，CAS 记 threadId）→ **轻量级锁**（线程交替竞争，自旋等待）→ **重量级锁**（竞争激烈，内核 mutex 挂起线程）——JDK6 后锁的自适应优化。

### 27. volatile 的作用？能保证原子性吗？⭐⭐⭐
💡 保证**可见性**（改完立刻刷主存，别人读不到旧值）+ **有序性**（内存屏障禁止指令重排）；**不保证原子性**——i++ 依旧丢更新，要原子用 AtomicInteger。

### 28. CAS 是什么？ABA 问题怎么解决？⭐⭐⭐
💡 Compare-And-Swap：CPU 级指令，"期望值没被改就换成新值"，无锁化的基础；ABA：值 A→B→A 被改回来了，CAS 察觉不到——**AtomicStampedReference 加版本号**解决。

### 29. AQS 的原理？⭐⭐⭐
💡 抽象队列同步器 = **volatile state + CLH 变体双向等待队列**；模板方法模式：子类只实现 tryAcquire/tryRelease，排队/阻塞/唤醒框架全包——ReentrantLock/Semaphore/CountDownLatch 全是它孩子。

### 30. 线程池的核心七参数？⭐⭐⭐
💡 corePoolSize（核心线程数）、maximumPoolSize（最大线程数）、keepAliveTime + unit（非核心线程空闲存活时间）、workQueue（任务队列）、threadFactory（线程工厂）、handler（拒绝策略）。

### 31. 线程池的执行流程？⭐⭐⭐（顺序是坑）
💡 核心线程未满→建核心；满了→**任务入队**；队列也满→才建非核心线程；到最大线程数→执行**拒绝策略**。坑点：先入队再开非核心，不是先开满线程！

### 32. 拒绝策略有哪些？参数怎么配合理？
💡 AbortPolicy 抛异常（默认）/ CallerRuns 调用者自己跑（反压）/ Discard 静默丢 / DiscardOldest 丢最老的。配置：CPU 密集 = 核数+1；**IO 密集 = 2×核数**或 `N×(1+等待时间/计算时间)`——AI 岗调 LLM 接口就是典型 IO 密集，线程数给大。

### 33. CountDownLatch 和 CyclicBarrier 的区别？⭐⭐
💡 CDL **一等多**（一个线程等其它 N 个 countDown 完再动，不可重置）；Barrier **多等多**（N 个线程互相等齐再一起冲，**可循环重置**、支持回调）——主线程汇总子任务用 CDL，并行批次同步用 Barrier。

### 34. ThreadLocal 的原理？为什么会内存泄漏？⭐⭐⭐
💡 每个 Thread 有个 ThreadLocalMap，key 是 ThreadLocal（**弱引用**），value 是值；ThreadLocal 被回收后 key 变 null 但 **value 还是强引用**，线程池里线程长活不销毁 → value 滞留泄漏。**铁律：用完 finally 里 remove()**。

### 35. 死锁的产生条件？怎么排查和避免？⭐⭐
💡 四条件：互斥、请求保持、不可剥夺、循环等待。排查：jstack 直接标出 deadlock，或 Arthas `thread -b`。避免：**按固定顺序加锁**、tryLock 设超时、缩小锁范围。

# 三、JVM（12 题）

### 36. JVM 运行时数据区（内存结构）？⭐⭐⭐
💡 线程私有：**程序计数器**（唯一不 OOM）、**虚拟机栈**（栈帧：局部变量表+操作数栈，过深 StackOverflow）、**本地方法栈**；线程共享：**堆**（对象实例，GC 主战场）、**方法区**（类元信息，JDK8 起由**元空间**实现，用本地内存）。

### 37. 堆的分代结构？对象怎么晋升老年代？⭐⭐⭐
💡 新生代 **Eden : S0 : S1 = 8:1:1** + 老年代；对象先在 Eden 出生，Minor GC 后进 Survivor，**每熬过一轮年龄+1，默认 15 岁**（对象头 4 bit 存年龄）晋升老年代；大对象直接进老年代（避免反复复制）。

### 38. 除了年龄到 15，对象还有哪些途径进老年代？
💡 ①大对象直接分配（-XX:PretenureSizeThreshold）②**动态年龄判断**：Survivor 中同龄对象总和超过一半，该岁数以上全部晋升 ③Minor GC 后 Survivor 放不下的，通过**空间分配担保**直接进老年代。

### 39. 类加载的过程？⭐⭐⭐
💡 **加载**（字节流→方法区的 Class 对象）→ **验证**（格式安全）→ **准备**（静态变量分配内存赋**默认值**，注意是 0 不是代码里的值）→ **解析**（符号引用→直接引用）→ **初始化**（执行 clinit，静态变量才真正赋值，**懒加载**）。

### 40. 双亲委派机制？为什么需要？怎么打破？⭐⭐⭐
💡 子加载器先委托父加载器，父加载不了自己再加载。好处：**安全**（防核心类被篡改，自己写个 java.lang.String 没用）+ **避免重复加载**。打破：SPI 的线程上下文类加载器、Tomcat webapp 隔离、OSGi/热部署。

### 41. 怎么判断对象能回收？GC Roots 有哪些？⭐⭐⭐
💡 **可达性分析**（从 Roots 向下搜索，不可达即垃圾，不用引用计数是因为循环引用没法处理）；Roots：虚拟机栈局部变量、静态变量、常量引用、JNI 引用、活跃线程对象。

### 42. 三大垃圾回收算法？⭐⭐
💡 **标记-清除**（简单但碎片多）、**复制**（无碎片但浪费一半空间——新生代两 Survivor 轮换用的就是它）、**标记-整理**（无碎片但移动对象慢——老年代用它）。

### 43. Minor GC / Full GC 的区别和触发条件？⭐⭐
💡 Minor GC：Eden 满，只收拾新生代，**频繁但快**；Full GC：老年代/元空间满、System.gc()、空间担保失败——**又慢又伤，调优就是减少 Full GC**。

### 44. 常见垃圾回收器怎么选（CMS/G1/ZGC）？⭐⭐⭐
💡 CMS：并发标记清除、低停顿，但**内存碎片+浮动垃圾**（JDK14 已移除，答个"历史使命完成"）；**G1**：Region 化分代、可预测停顿目标，大堆主流（JDK9+ 默认）；**ZGC**：染色指针+读屏障，**亚毫秒级停顿**，JDK21 支持分代——2026 AI 高并发服务的新宠。

### 45. 内存泄漏和内存溢出的区别？
💡 泄漏：对象**该死没死**（无用了还被引用，如 ThreadLocal 不 remove、静态集合只增不减），泄漏攒多了就溢出；溢出：内存**真的不够用**（OOM）——泄漏是病根，溢出是症状。

### 46. OOM 怎么排查？⭐⭐⭐
💡 参数 `-XX:+HeapDumpOnOutOfMemoryError` 留现场 → dump 文件喂给 **MAT/JProfiler** 看支配树，找占内存最大的对象 → 顺藤摸瓜定位代码（常见元凶：大查询一次拉全表、静态缓存无限增长、ThreadLocal）。

### 47. JVM 调优常用命令和工具？⭐⭐
💡 jps（找进程）、jstat -gcutil（看 GC 频率）、jmap -dump（抓堆）、jstack（抓线程栈，查死锁/CPU 高）；生产在线神器 **Arthas**：dashboard 一屏看全局、thread -n 3 找最忙线程、heapdump 不重启抓现场。

# 四、Spring 核心（15 题）

### 48. IOC 是什么？有什么好处？⭐⭐⭐
💡 控制反转：对象的创建和管理权从"自己 new"反转给**容器**，DI（依赖注入）是实现方式。好处：解耦（面向接口）、可测试（单测直接注入 mock 对象）、统一生命周期管理。

### 49. DI 三种注入方式？推荐哪种？⭐⭐
💡 字段注入（@Autowired 打字段，简洁但离不开容器）、setter 注入、**构造器注入（官方推荐）**：依赖不可变（final）、必填项一目了然、单测直接 new。注意：构造器注入遇循环依赖直接报错，反过来这也是设计坏味道的信号。

### 50. Bean 的创建方式有哪些？
💡 ①@Component+包扫描（自有类）②@Bean 方法（**第三方 jar 的类**没法加注解）③@Import（快速导入）④FactoryBean（创建逻辑复杂时定制工厂）。

### 51. @Component / @Service / @Repository / @Controller 有区别吗？
💡 **功能上没区别**（都是注册组件，扫描一视同仁），纯粹是**语义分层**：Controller 表现层 / Service 业务层 / Repository 持久层 / Component 通用——代码可读性 + 特定层附加功能（如 Repository 触发持久化异常翻译）。

### 52. Bean 的作用域有哪些？⭐⭐
💡 **singleton**（默认，容器一份）、**prototype**（每次 getBean 新建）、web 环境：request（一次请求）、session（一会话）、application、websocket。有状态 Bean 用 singleton 会出并发 bug！

### 53. Spring 的 singleton 和单例模式的区别？⭐⭐
💡 Spring singleton 是**容器范围**的单例（一个容器一份，可以自己 new、多个容器就有多份）；单例模式是 **JVM/类加载器范围**（构造器私有，全局唯一）——范围不同，严格说 Spring 是"单例 Bean"不是单例模式。

### 54. Bean 的生命周期？⭐⭐⭐
💡 实例化（构造器）→ **属性填充**（@Autowired 注入）→ Aware 回调 → BeanPostProcessor 前置 → @PostConstruct → InitializingBean.afterPropertiesSet → init-method → BeanPostProcessor 后置（**AOP 代理就在这里生成**）→ 使用 → @PreDestroy → destroy-method。

### 55. @PostConstruct / afterPropertiesSet / init-method 的执行顺序？⭐⭐
💡 **@PostConstruct → InitializingBean.afterPropertiesSet → init-method**（注解 → 接口 → 配置，注解最优先）；销毁对称：@PreDestroy → DisposableBean.destroy → destroy-method。

### 56. AOP 是什么？核心概念速记？⭐⭐⭐
💡 面向切面：把日志/事务/权限等**横切逻辑**从业务代码抽离。五术语：JoinPoint 连接点（可织入的方法）、**Pointcut 切点**（真正匹配到的方法表达式）、**Advice 通知**（干什么）、Aspect 切面（=切点+通知）、Weaving 织入（代理生成时机）。

### 57. AOP 五种通知类型？
💡 @Before（前置）、@After（后置 finally 必走）、@AfterReturning（正常返回后，能拿返回值）、@AfterThrowing（抛异常后，能拿异常）、**@Around（环绕最强，手动 proceed() 包住全部）**。

### 58. JDK 动态代理和 CGLIB 的区别？⭐⭐⭐
💡 JDK：**基于接口**，反射 Proxy.newProxyInstance + InvocationHandler；CGLIB：**基于继承**生成字节码子类，final 类/方法搞不了。Spring：有接口默认 JDK，无接口 CGLIB；**Boot 2 起默认统一 CGLIB**（避免注入类型问题）。

### 59. AOP 什么情况下会失效？⭐⭐（同事务失效的根）
💡 **自调用**：同类里 this.methodB() 走的是原始对象不是代理，切面/事务全失效。解法：AopContext.currentProxy()、注入自身代理、或把方法拆到另一个 Bean。

### 60. @Transactional 有哪些失效场景？⭐⭐⭐（八连背）
💡 ①方法非 public ②**自调用**（this 调用不走代理）③异常被 try-catch **吞了** ④默认只回滚 RuntimeException/Error，**受检异常要 rollbackFor = Exception.class** ⑤类没被 Spring 管理（没注解）⑥传播行为配错 ⑦多线程里调用（事务绑定 ThreadLocal 连接）⑧数据库引擎不支持（MyISAM）。

### 61. 事务的传播行为？重点讲两个？⭐⭐⭐
💡 7 种，重点两个：**REQUIRED**（默认：有事务就加入，没有就新建——绝大多数场景）；**REQUIRES_NEW**（挂起当前事务，**新开独立事务**，互不影响——记操作日志/发通知不怕主事务回滚带走）；还有 NESTED（嵌套保存点，可局部回滚）等。

### 62. 循环依赖是什么？三级缓存怎么解决？⭐⭐⭐
💡 A 依赖 B、B 又依赖 A。三级缓存：一级 singletonObjects（**成品**）、二级 earlySingletonObjects（**半成品早期引用**）、三级 singletonFactories（**工厂**，可生成早期引用，兼顾 AOP 代理提前）。流程：A 实例化后先把自己的工厂放三级 → 填充时发现要 B → B 创建时要 A → 从三级缓存拿 A 的早期引用（升级到二级）→ B 完成 → A 拿到 B 继续完成。**构造器注入和 prototype 无解**。
