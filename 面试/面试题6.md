# 一、MySQL（22 题）

### 1. SQL 语言的四大门派？⭐⭐⭐
💡 DDL **盖房**（CREATE/DROP/ALTER 管结构）、DML **搬家具**（INSERT/UPDATE/DELETE 管数据）、DQL **找东西**（SELECT 查数据）、DCL **发钥匙**（GRANT/REVOKE 管权限）。

### 2. 关系型和非关系型数据库的区别？⭐⭐
💡 关系型（MySQL）：表格结构、表间有关系、SQL 强大、支持 ACID 事务；非关系型（Redis/MongoDB/ES）：键值/文档等灵活结构、高并发读写强，但事务支持一般较弱。**要一致选关系，要性能灵活选非关系**。

### 3. CHAR 和 VARCHAR 的区别？⭐⭐
💡 CHAR **定长**（不足补空格，浪费但快，适合手机号/身份证）；VARCHAR **变长**（用多少占多少 + 1~2 字节长度记录，省空间，适合姓名/地址）。

### 4. 存金额为什么不能用 FLOAT/DOUBLE？用什么？⭐⭐⭐
💡 浮点数有**精度误差**（0.1 + 0.2 ≠ 0.3 的经典惨案），钱必须用 **DECIMAL(M,D)** 精确小数，分钱也可以用 BIGINT 存。

### 5. DROP / TRUNCATE / DELETE 区别？⭐⭐⭐
💡 DELETE 是 **DML**：逐行删、可带 WHERE、**可回滚**、保留自增计数；TRUNCATE 是 **DDL**：重建表、快、不可回滚、自增 ID 归零；DROP 连**表结构一起删**。忘写 WHERE 的 DELETE/UPDATE = 全表遭殃，执行前先 SELECT 确认范围！

### 6. WHERE 和 HAVING 的区别？⭐⭐
💡 WHERE 在**分组前**过滤原始行（不能用聚合函数）；HAVING 在**分组后**过滤分组结果（可以用 COUNT/SUM 等聚合）。

### 7. 内连接和外连接的区别？⭐⭐⭐
💡 内连接取两表**交集**；左外连接保留**左表全部**，右表没匹配的补 NULL；右外连接反过来；全外连接 MySQL 不直接支持，用 UNION 模拟。

### 8. IN 和 EXISTS 怎么选？⭐⭐
💡 核心口诀**小表驱动大表**：子查询结果集小用 **IN**（先执行子查询）；外层表小、子查询表大用 **EXISTS**（对外层每行判断子查询是否有匹配）。

### 9. COUNT(*) / COUNT(1) / COUNT(字段) 区别？⭐⭐
💡 COUNT(*) 和 COUNT(1) 统计**所有行**（InnoDB 官方专门优化过，不会取值）；COUNT(字段) **忽略 NULL**。统计总数无脑 COUNT(*)。

### 10. MySQL 有哪些约束？⭐⭐
💡 PRIMARY KEY（主键 = 唯一 + 非空）、NOT NULL、UNIQUE、DEFAULT、CHECK；FOREIGN KEY 外键互联网公司一般**不用**（性能拖累），靠代码逻辑维护。

### 11. MySQL 为什么用 B+ 树而不是 B 树 / 哈希？⭐⭐⭐
💡 三个杀手锏：① 非叶子节点**只存键不存数据** → 单页放更多键 → 树更**矮胖**（3~4 层撑千万数据）→ 磁盘 IO 更少；② 叶子节点用**双向链表串联** → 范围查询、排序顺着链表扫就行；③ 对比哈希：哈希等值 O(1) 快但**不支持范围查询和排序**。

### 12. 聚簇索引和非聚簇索引？什么是回表？⭐⭐⭐
💡 聚簇索引（主键索引）：叶子节点存**整行数据**；非聚簇索引（二级索引）：叶子节点存**主键值** → 拿主键再回主键树查一遍完整数据就叫**回表**（查了两棵树，多一次 IO）。

### 13. 联合索引的最左前缀原则？⭐⭐⭐
💡 联合索引 (a,b,c) 按 a→b→c 排序存储，查询条件必须**从最左列开始连续命中**才能走索引：`a`、`a,b` ✅；`b`、`b,c` ❌（跳过 a 直接用 b 等于没有目录可查）。遇到范围查询（>、LIKE%）后面的列还会失效。

### 14. 什么是覆盖索引？⭐⭐
💡 查询的字段**全部包含在索引里**，叶子节点直接拿到结果，**不用回表**。EXPLAIN 里 Extra 显示 `Using index` 就是它——性能提升大杀器。

### 15. 哪些情况索引会失效？⭐⭐⭐
💡 五大坑：① 索引列上做**函数/运算**；② LIKE 以 **% 开头**；③ 发生**隐式类型转换**（字符串列传数字）；④ 条件用 **OR** 连接了无索引列；⑤ **违反最左前缀**原则。

### 16. 事务的 ACID？⭐⭐⭐
💡 **原子性**（Atomicity：全做或全不做，靠 undo log 回滚）、**一致性**（Consistency：从一个一致状态到另一个一致状态，是最终目的）、**隔离性**（Isolation：事务之间互不干扰，靠锁 + MVCC）、**持久性**（Durability：提交即落盘，靠 redo log）。

### 17. 脏读、不可重复读、幻读分别是什么？⭐⭐⭐
💡 **脏读**：读到别人**还没提交**的数据（人家一回滚你就读了寂寞）；**不可重复读**：同一事务两次读同一行**值变了**（被别人 UPDATE）；**幻读**：两次读同一范围**行数变了**（被别人 INSERT/DELETE，冒出新行像幻觉）。

### 18. 四大隔离级别？MySQL 默认哪个？⭐⭐⭐
💡 从松到严：读未提交（脏读）→ 读已提交（避免脏读）→ **可重复读 RR（MySQL 默认**，避免脏读+不可重复读）→ 串行化（全解决但性能最差）。

### 19. RR 级别怎么解决幻读？⭐⭐⭐
💡 InnoDB 在 RR 下用 **MVCC + 间隙锁（Next-Key Lock）**在很大程度上解决幻读：快照读靠 **MVCC** 多版本读旧快照，当前读靠**间隙锁**锁住区间阻止别人 INSERT。

### 20. InnoDB 和 MyISAM 的区别？⭐⭐
💡 InnoDB：**支持事务 + 行级锁 + 外键 + 崩溃自动恢复**（redo log），MySQL 5.5 后默认；MyISAM：不支持事务、**表锁**、崩溃易坏，但 COUNT(*) 无条件时直接读存的行数快。现在基本无脑 InnoDB。

### 21. EXPLAIN 主要看哪几列？⭐⭐
💡 **type**（访问级别：const > eq_ref > ref > range > index > ALL，至少要到 range，ALL 全表扫描要警惕）、**key**（实际用的索引）、**rows**（预估扫描行数）、**Extra**（`Using index` 覆盖索引好；`Using filesort` 额外排序坏）。

### 22. 深分页 LIMIT 1000000,10 为什么慢？怎么优化？⭐⭐⭐
💡 要扫描并**丢弃前 100 万行**再取 10 条。优化：① **游标法**：`WHERE id > 上一页最大id LIMIT 10`，顺着索引往下走（最优，但只能顺序翻页）；② **延迟关联**：先用覆盖索引查出 10 个 id，再回表取整行。

# 二、Redis（21 题）

### 23. Redis 为什么这么快？⭐⭐⭐
💡 ① 纯**内存**操作；② **单线程**命令执行，无锁竞争、无上下文切换；③ **IO 多路复用**（epoll）单线程监听海量连接；④ 底层**数据结构**专治各种场景（SDS/跳表/压缩列表等）。

### 24. Redis 五大基础类型及典型场景？⭐⭐⭐
💡 **String** 缓存/计数器/验证码/分布式锁；**Hash** 存对象、购物车；**List** 消息队列、最新列表；**Set** 去重、共同好友、抽奖；**ZSet** 排行榜、延时队列。

### 25. 存对象用 String 还是 Hash？⭐⭐
💡 整存整取用 String（存 JSON）；**频繁改单个字段**用 Hash——`HSET user:1 age 19` 一步到位，而 String 存 JSON 得「取出整个 → 反序列化改 → 存回」三连，还整个对象来回跑网络。

### 26. List 怎么当简易消息队列？⭐⭐
💡 生产者 `LPUSH`，消费者 `BRPOP`（**阻塞式**弹出，没数据就等），一进一出天然有序；缺点：无 ACK 机制、宕机丢消息，生产级还是上专业 MQ。

### 27. Set 的集合运算能干嘛？⭐⭐
💡 **SINTER 交集**→ 共同好友；**SUNION 并集** → 所有好友；**SDIFF 差集** → 我关注但对方没关注；**SRANDMEMBER/SPOP** → 抽奖随机抽。

### 28. ZSet 为什么是排行榜专业户？⭐⭐⭐
💡 每个成员带 **score 自动排序**：`ZADD` 加分进榜、`ZREVRANGE 0 2` 直接取前三领奖台、`ZINCRBY` 实时加分、`ZRANK` 查排名——全 O(logN)，比 MySQL `ORDER BY` 香太多。

### 29. 三种特殊类型及场景？⭐⭐
💡 **Bitmap** 位图：一串 0/1 格子超省空间 → 签到（`SETBIT`/`BITCOUNT`，一个月才 31 个比特）、活跃统计；**HyperLogLog**：0.81% 误差换百万 UV 只占约 **12KB**（`PFADD`/`PFCOUNT`）；**GEO**：存经纬度 → 附近的人、附近的店（`GEOADD`/`GEOSEARCH`）。

### 30. 为什么生产环境禁用 KEYS *？⭐⭐
💡 KEYS 一次性遍历**所有 key 会阻塞**单线程的主线程，卡死全部请求。用 **SCAN** 渐进式分批遍历（`SCAN 0 MATCH user:* COUNT 100`），每次只扫一小撮。

### 31. RDB 和 AOF 的区别？⭐⭐⭐
💡 **RDB**：定时**全量快照**（fork 子进程 dump 二进制），文件小恢复快，但两次快照之间的数据会丢；**AOF**：记录每条**写命令**（append），丢得少，但文件大、恢复慢（重放命令）。AOF 刷盘策略 everysec 兼顾性能与安全。

### 32. 混合持久化是什么？⭐⭐
💡 Redis 4.0+ 方案：AOF 重写时先写入**全量 RDB 格式**头，后续增量用 AOF 命令——**恢复快（RDB 部分）+ 丢得少（AOF 部分）**，两全其美，4.0 后的主流选择。

### 33. 过期 key 是怎么删除的？⭐⭐
💡 **惰性删除**：访问时发现过期才删（省 CPU 但冷数据占内存）+ **定期删除**：后台周期性随机抽查一批带过期时间的 key 删掉——两者配合兜底。

### 34. 内存满了怎么办？淘汰策略有哪些？⭐⭐⭐
💡 8 种策略：不淘汰（默认 **noeviction**：写请求报错）+ 淘汰带 TTL 的（volatile-lru/lfu/random/ttl）+ 淘汰全部 key 的（**allkeys-lru**/allkeys-lfu/allkeys-random）。**缓存场景最常用 allkeys-lru**（淘汰最久没用的）。

### 35. Redis 事务和 MySQL 事务的区别？⭐⭐⭐
💡 Redis 事务（MULTI/EXEC）只是**把命令攒起来顺序执行**：① **不保证原子性**——某条命令运行时出错，其余照常执行；② **没有回滚**。MySQL 事务才是一个事务内出错全部回滚，真正的 ACID。

### 36. 为什么 Lua 脚本能保证原子性？⭐⭐
💡 Redis 单线程执行命令，Lua 脚本会被**当成一条命令整体执行**，期间不会插入其他客户端命令——所以「判断 + 操作」多步逻辑用 Lua 包起来就是原子的。

### 37. 主从复制解决什么问题？⭐⭐
💡 **读写分离**（主写从读，扛住读流量）+ **数据冗余容灾**（主挂了从还有完整数据）；全量同步（RDB）+ 增量同步（repl_backlog 缓冲区）。

### 38. 哨兵机制的工作原理？⭐⭐
💡 哨兵盯着主节点：一个哨兵 ping 不通 → **主观下线**；超过 quorum 个哨兵都认为挂了 → **客观下线**；然后哨兵之间**投票选出一个**执行故障转移——挑从节点升主、通知其他从改主、客户端更新地址。

### 39. 集群模式的 16384 槽是怎么回事？⭐⭐
💡 Redis Cluster 把 key 空间分成 **16384 个哈希槽**，`CRC16(key) % 16384` 算出 key 属于哪个槽，槽再分配给各个主节点；每个主带从做高可用。**数据分片**多主同时写，容量和写入性能横向扩展。

### 40. 缓存穿透、击穿、雪崩？⭐⭐⭐
💡 **穿透**：查**根本不存在**的数据，缓存永远不命中全砸 DB → 缓存空值 / **布隆过滤器**；**击穿**：单个**热点 key 过期**瞬间海量请求砸 DB → 互斥锁重建 / 逻辑过期 / 热点不过期；**雪崩**：**大量 key 同时过期**或 Redis 整个挂了 → 过期时间**加随机值**、集群高可用、限流降级保底。

### 41. 缓存和数据库的一致性怎么保证？⭐⭐⭐
💡 主流 **Cache Aside 旁路缓存**：读→先查缓存， miss 查 DB 回填；写→**先更新 DB，再删除缓存**（删而不是更新：懒加载思想，避免并发写产生脏数据）。要更强一致性再加延迟双删 / 订阅 binlog（Canal）异步删。

### 42. Redis 分布式锁怎么做才对？⭐⭐⭐
💡 四步防四坑：① 加锁必须一条命令 `SET lock uuid NX EX 10`（**原子**，拆成 SETNX+EXPIRE 两步会在中间宕机死锁）；② value 存**唯一标识**，解锁用 **Lua 脚本**「比对是自己的锁再删」（防误删别人的）；③ 业务超时锁过期 → **Redisson 看门狗**自动续期；④ 主从切换锁丢失 → RedLock（了解即可）。

# 三、ElasticSearch（12 题）

### 43. ES 是什么？为什么搜索不用 MySQL 的 LIKE？⭐⭐
💡 分布式**全文检索引擎**。LIKE '%xx%' **无法走索引全表扫**，且没有分词、相关度排序、高亮这些能力；ES 靠**倒排索引 + 分词**，海量数据毫秒级模糊搜索，是天生的搜索引擎。

### 44. ES 的概念和 MySQL 怎么类比？⭐⭐
💡 **Index 索引 ≈ 表**、**Document 文档 ≈ 行**（JSON 结构）、**Field 字段 ≈ 列**、**Mapping ≈ 表结构定义**（字段类型，建索引时定好）。

### 45. 正排索引和倒排索引的区别？⭐⭐⭐
💡 正排：**id → 文档内容**（人找词，想查含某词的文档得挨个翻）；倒排：**词 → 文档 id 列表**（**词找人**，分词后建好词典，搜「红」直接拿到所有含「红」的文档 id）——全文检索的核心就是倒排。

### 46. 倒排索引由哪几部分组成？⭐⭐
💡 三件套：**Term Dictionary 词典**（所有切出来的词项）、**Term Index 词典索引**（FST 压缩结构常驻内存，快速定位词典位置，类比书的目录的目录）、**Posting List 倒排列表**（含该词的文档 id + 词频 + 位置）。

### 47. IK 分词器的两种模式怎么配合？⭐⭐
💡 **ik_max_word** 最细粒度切分（「中华人民共和国」→ 一大堆词，**建索引时用**，保证召回）；**ik_smart** 粗粒度切分（词条少，**搜索时用**，效率高）——「**索引最细、搜索最粗**」双剑合璧。

### 48. text 和 keyword 类型的区别？⭐⭐⭐
💡 **text 会分词**：全文检索用（商品标题、文章内容）；**keyword 不分词**：整体精确匹配（订单号、状态、标签），以及排序和聚合。同一个字段可同时定义 `title`（text）+ `title.keyword` 双 mapping。

### 49. match 和 term 查询的区别？⭐⭐⭐
💡 **match**：先对搜索词**分词**再逐个查（OR/AND 合并结果）→ 全文检索；**term**：**不分词**整词精确匹配 → 查 keyword、数字、日期。坑：对 text 字段用 term，搜的词已经被分过了，经常查不到。

### 50. match_phrase 和 match 的区别？⭐⭐
💡 match_phrase 分词后要求**全部命中 + 顺序一致 + 位置相邻**（真正的「短语匹配」）；match 分出来的词谁出现都算。`slop` 参数可放宽相邻要求（允许隔几个词）。

### 51. bool 查询的四个子句？⭐⭐
💡 **must**（必须匹配，参与打分）、**should**（应该匹配，参与打分）、**must_not**（必须不匹配，**不打分**）、**filter**（必须匹配，**不打分但可缓存**）——过滤条件尽量放 filter，性能更好。

### 52. ES 聚合有哪两大类？⭐⭐
💡 **桶聚合 bucket**（分组：terms 按字段值分桶统计数量，类比 GROUP BY）+ **指标聚合 metrics**（算值：avg/max/min/sum，类比聚合函数）；两者可以嵌套（先分桶再对每桶算指标）。

### 53. 分片和副本？分片数能改吗？⭐⭐
💡 **主分片**数量建索引时就**定死**（要改只能重建索引 reindex），**副本数可动态调整**；分片把数据水平拆到多节点（扩容量），副本提供**高可用 + 读扩展**。分片不是越多越好（每个分片有开销）。

### 54. 什么是 NRT 近实时？⭐⭐
💡 写入先进 memory buffer + translog，默认每隔 **1 秒 refresh** 生成新 segment 才能被搜到——所以 ES 是**近实时（约 1 秒延迟）**而不是真实时；translog 保证这段窗口期数据不丢。

# 四、MongoDB（10 题）

### 55. MongoDB 是什么？什么场景用？⭐⭐
💡 **文档型数据库**：数据以 BSON（类 JSON）文档存储，结构灵活（字段随便加）、无需提前定义表结构、支持嵌套——适合**字段多变、嵌套结构、高写入**的场景：日志、用户行为、内容管理、IoT 数据。

### 56. 聚合管道是什么？⭐⭐⭐
💡 把多个阶段（stage）像**流水线**一样串起来，文档流过一节节「加工车间」得出统计结果：`$match`（过滤，**尽量放最前面**能借索引）→ `$group`（分组统计）→ `$sort` → `$project`（挑字段）——类比 SQL 的 WHERE/GROUP BY/ORDER BY/SELECT。

### 57. $unwind 和 $lookup 是干嘛的？⭐⭐
💡 **$unwind**：把数组字段「拆开」，一行变多行（订单拆成每个商品一行再统计）；**$lookup**：关联查询，相当于 SQL 的**左外连接**（关联另一集合把匹配数据塞进数组）。

### 58. MongoDB 的索引有什么特别的？⭐⭐
💡 底层用 **B 树**（非叶子节点也带数据，单点查询快，契合文档查询模式）；特色索引：**TTL 索引**——按时间字段自动过期删文档（日志、验证码、会话自动清理神器）、复合索引、地理索引等。

### 59. 副本集是怎么工作的？⭐⭐
💡 一主多从，主节点挂了**剩余节点自动投票选举**出新主（**自带选举，不用像 Redis 那样单独部署哨兵**）；写默认打主节点、异步同步到从节点。

### 60. Write Concern 是什么？⭐⭐
💡 写安全级别：`w:0`（发出就行不等确认，最快但可能丢）、`w:1`（主节点确认，默认）、`w:majority`（**多数节点确认**才返回，最安全但慢）——写性能和数据安全的调节旋钮。

### 61. 分片集群由哪些角色组成？⭐⭐
💡 **mongos 路由**（接收请求，按分片键路由到对应分片，客户端只连它）+ **Config Server**（存元数据：哪些数据在哪个分片）+ **Shard 分片**（真正存数据的 mongod，每个分片建议做成副本集）。

### 62. 分片键怎么选？选错了会怎样？⭐⭐⭐
💡 三个标准：**高基数**（取值足够多才能拆得开）、**查询常带**（大多数查询带分片键，才能直达单分片）、**写入均匀**（单调递增的 id/时间会把写全砸一个分片成热锅）。关键：**分片键定了几乎不能改**，改 = 重建集合。

### 63. MongoDB 的事务和 MySQL 有什么不同？⭐⭐
💡 设计哲学不同：**单文档操作天生原子**（文档可以嵌套，一次写完，压根不需要跨文档事务）——优先靠**合理嵌入文档设计**规避事务；4.0+ 也支持多文档事务（副本集），但有性能代价，能不用就不用。

### 64. 新手常踩的坑有哪些？⭐⭐
💡 ① update 忘写 **$set** → 整个文档被替换，其他字段全丢；② 单文档 **16MB 上限** → 无限增长的数组别硬塞一个文档；③ **skip 深分页**很慢 → 学 MySQL 用游标（range 查询）翻页。

# 五、四方对决 · 综合战场（3 题）

### 65. MySQL / Redis / ES / MongoDB 一句话定位？⭐⭐⭐
💡 口诀：**强一致存 MySQL，要快用 Redis，要搜用 ES，要灵活用 MongoDB**——MySQL 是数据的家（最终一致性兜底），Redis 是内存加速器（缓存/锁/排行榜），ES 是搜索引擎（全文检索/聚合分析），MongoDB 是灵活文档仓（多变结构/高写入）。

### 66. 一个内容平台的四方是怎么配合的？⭐⭐⭐
💡 **写**：内容先落 **MySQL**（主数据）→ 通过 MQ 同步到 **ES**（建倒排索引供搜索）→ 删除/更新相关 **Redis** 缓存。**读**：详情页先查 **Redis** 缓存 → miss 回源 MySQL；搜索页查 **ES**（关键词 + 分词 + 相关度排序）；用户行为日志写 **MongoDB**（结构灵活好扩展）——各司其职，谁也不越界。

### 67. 新需求来了，怎么判断用哪个？⭐⭐
💡 三连问：① **要不要事务强一致**？要 → MySQL；② **读得多不多、能不能接受最终一致**？能 → Redis 缓存；③ **是关键词搜索还是精确查询**？搜索 → ES，精确 → MySQL；④ **结构经常变、嵌套深、写入大**？→ MongoDB。答案往往不是二选一，而是**组合拳**。
