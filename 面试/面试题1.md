# 一、Java 基础与集合（15 题）

### 1. == 和 equals 的区别？⭐⭐⭐
💡 **==** 比较引用地址（基本类型比值）；**equals** 比较内容，可重写。
📖 铁律：equals 相等 → hashCode 必须相等，否则 HashMap 里"相等"对象会存两份。

### 2. String 为什么设计成不可变？⭐⭐⭐
💡 三大理由：线程安全（天然共享）、hash 可缓存（String 的 hashCode 惰性计算存起来）、安全性（防类名/路径被篡改）。
📖 实现：final 类 + private final byte[] 数组；每次"修改"都产生新对象。

### 3. `String s = new String("abc")` 创建几个对象？
💡 最多 2 个：常量池的 "abc"（若不存在）+ 堆里 new 出来的对象。
📖 考点其实是字符串常量池；`intern()` 可手动把引用入池。

### 4. HashMap 的 put 流程？⭐⭐⭐
💡 hash 扰动定位桶 → 空桶直接放；key 相同则覆盖，不同挂链表**尾部**；链表 ≥8 且数组 ≥64 树化；元素超 容量×0.75 则 2 倍扩容。
📖 扰动函数 `(h = keyHash) ^ (h >>> 16)` 让高位参与运算减少碰撞；1.7 头插死循环、1.8 改尾插。

### 5. HashMap 容量为什么是 2 的幂？
💡 `(n-1) & hash` 等价取模但更快；扩容时元素要么留原位、要么挪 oldCap，分布均匀。
📖 位运算替代 `%` 是性能关键；构造传 17 会自动抬到 32。

### 6. ConcurrentHashMap 1.8 怎么保证线程安全？⭐⭐⭐
💡 空桶 CAS 插入，非空桶 synchronized 锁**桶头节点**（锁粒度=单桶）；size 用 CounterCell 分段累加。
📖 对比 1.7 分段锁（Segment）并发度更高；扩容时多线程协助迁移（helpTransfer）。

### 7. fail-fast 和 fail-safe？
💡 ArrayList 迭代中修改 → 抛 ConcurrentModificationException（fail-fast）；CopyOnWriteArrayList 迭代的是旧数组快照（fail-safe）。
📖 modCount 版本号机制；COW 适合读多写极少（如监听器列表）。

### 8. ArrayList 扩容机制？
💡 首次 add 分配默认容量 10，之后 1.5 倍扩容（oldCap + oldCap>>1），Arrays.copyOf 整体搬迁。
📖 已知数据量时构造传初始容量，避免反复复制。

### 9. 接口和抽象类怎么选？
💡 **is-a** 亲缘关系用抽象类（单继承、可带状态和构造器）；**can-do** 能力附加用接口（可多实现、JDK8+ 有 default 方法）。
📖 模板方法模式 → 抽象类；给类附加能力（Comparable）→ 接口。

### 10. 重载和重写的区别？
💡 重载：同类、同名、参数列表不同，编译期确定；重写：父子类、同签名，运行期多态。
📖 重写口诀"两同两小一大"：方法名参数同，返回值和异常范围小，访问权限大。

### 11. 深拷贝和浅拷贝？
💡 浅拷贝只复制一层（引用字段共享对象）；深拷贝递归复制整个对象图。Object.clone() 默认浅拷贝。
📖 实现深拷贝：递归 clone / 序列化往返 / JSON 序列化（Jackson 深拷贝最省事）。

### 12. Java 异常体系？⭐⭐
💡 Throwable → Error（OOM 等不可恢复）/ Exception；Exception 分受检异常（编译器强制处理）和 RuntimeException。
📖 业务自定义异常继承 RuntimeException 即可；全局统一 @RestControllerAdvice 捕获。

### 13. JDK8 你常用哪些特性？
💡 Lambda、Stream API、Optional、接口 default 方法、LocalDateTime、元空间替代永久代。
📖 Stream 惰性求值：中间操作不执行，终端操作才触发；并行流默认走 ForkJoinPool.commonPool。

### 14. JDK17/21（LTS）新特性？⭐⭐（AI 岗新宠）
💡 17：record、sealed 类、switch 模式匹配；21：**虚拟线程正式版**、分代 ZGC、结构化并发（预览）。
📖 SpringBoot3 强制 JDK17+；AI 应用高并发 IO 场景答虚拟线程是加分项。

### 15. 反射的原理和代价？
💡 运行期读取 Class 元信息，动态访问字段/方法/构造器；比直接调用慢（检查+装箱），可用 setAccessible + 缓存 Method 优化。
📖 Spring/MyBatis 等框架基石；GraalVM Native Image 下反射需提前注册。

# 二、并发编程（13 题）

### 16. Java 创建线程有几种方式？
💡 严格说只有 `new Thread()` 一种；Runnable/Callable/线程池都是"任务"的封装形式。
📖 面试官真正想听：生产用线程池，阿里规约禁止 Executors 直接创建。

### 17. 线程池 7 参数和执行流程？⭐⭐⭐
💡 corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。流程：核心满 → 入队 → 队满开非核心 → 到顶走拒绝策略。
📖 拒绝策略 4 种：AbortPolicy(抛异常)/CallerRuns(调用者执行)/Discard/DiscardOldest。

### 18. 为什么禁止用 Executors 创建线程池？
💡 newFixedThreadPool 用无界 LinkedBlockingQueue，堆积任务可 OOM；newCachedThreadPool 最大线程 Integer.MAX_VALUE，线程爆炸。
📖 正确姿势：手动 new ThreadPoolExecutor，明确所有参数+有界队列。

### 19. sleep 和 wait 的区别？⭐⭐⭐
💡 sleep 是 Thread 方法、**不释放锁**；wait 是 Object 方法、**释放锁**，必须在 synchronized 内调用，靠 notify/notifyAll 唤醒。
📖 wait/notify 是锁（monitor）的协作机制，和锁绑定所以定义在 Object。

### 20. volatile 的作用？⭐⭐⭐
💡 保证**可见性**（写立即刷主存、读使其他核缓存失效）和**有序性**（禁止指令重排），**不保证原子性**。
📖 底层是内存屏障；经典应用：DCL 单例防"半成品对象"、状态标志位。

### 21. synchronized 锁升级过程？
💡 无锁 → 偏向锁（单线程反复获取）→ 轻量级锁（CAS 自旋）→ 重量级锁（OS 互斥量，涉及内核态）。
📖 加分点：JDK15 起偏向锁默认废弃（维护成本高于收益）；锁信息存在对象头 Mark Word。

### 22. CAS 原理？ABA 问题？
💡 Compare-And-Swap，CPU 指令级原子操作：值等于预期才更新；ABA 用版本号（AtomicStampedReference）解决。
📖 缺点：自旋空耗 CPU、只能保证单变量；LongAdder 分段累加解决高并发计数竞争。

### 23. AQS 原理？⭐⭐
💡 AbstractQueuedSynchronizer = volatile int state + CLH 双向等待队列；获取失败入队 park，释放时 unpark 后继。
📖 独占模式（ReentrantLock）/共享模式（Semaphore、CountDownLatch）；公平锁=入队前先看队列有没有前驱。

### 24. ThreadLocal 原理和内存泄漏？⭐⭐⭐
💡 每个 Thread 持有 ThreadLocalMap，key 是 ThreadLocal 的**弱引用**；线程池线程不死，key 被回收后 value 访问不到仍占内存。
📖 解决：finally 中 remove()；父子传递用 TransmittableThreadLocal（TTL）。

### 25. 死锁的条件和排查？
💡 四必要条件：互斥、持有并等待、不可剥夺、循环等待。排查：jstack 看 "Found one Java-level deadlock"。
📖 预防：固定加锁顺序、tryLock 设超时、一次性申请所有资源。

### 26. CountDownLatch 和 CyclicBarrier 区别？
💡 Latch 倒计时一次性（主线程等 N 个子任务完成）；Barrier 可 reset 循环用（N 个线程互等，到齐一起走）。
📖 都基于 AQS 共享模式；类似物 Semaphore 控制并发数。

### 27. 虚拟线程的原理和适用场景？⭐⭐⭐（2026 高频）
💡 JVM 调度的用户态线程，由载体平台线程承载；IO 阻塞时自动 unmount 让出载体 → 百万级并发。适合 **IO 密集**。
📖 坑：synchronized 长阻塞会 pin 住载体线程（JDK24 优化）、不要池化、慎用 ThreadLocal（百万线程=百万份副本）。

### 28. CompletableFuture 怎么编排异步任务？
💡 supplyAsync 提交、thenApply 链式转换、thenCombine 合并两个、allOf 等全部、exceptionally 兜底。
📖 必须传自定义线程池，否则默认 commonPool 打满拖垮全局；AI 场景"并行调多个模型取最快"常用 applyToEither。

# 三、JVM（8 题）

### 29. JVM 运行时内存区域？⭐⭐⭐
💡 线程私有：程序计数器、虚拟机栈、本地方法栈；线程共享：堆、元空间（本地内存）+ 直接内存。
📖 JDK8 起永久代改元空间（本地内存），受 `-XX:MaxMetaspaceSize` 限制，动态类加载不再挤爆堆。

### 30. 对象什么时候进老年代？
💡 年龄达标（默认 15 次 Minor GC 存活）、大对象直接进（PretenureSizeThreshold）、动态年龄判断（同龄对象超 Survivor 一半）、Minor GC 后存活对象放不下。
📖 年龄记录在对象头 Mark Word 中；-XX:MaxTenuringThreshold 可调。

### 31. 哪些是 GC Roots？
💡 虚拟机栈局部变量、静态变量、常量引用、JNI 引用。口诀"**栈静常 JNI**"。
📖 可达性分析从 Roots 出发；对比引用计数法，天然解决循环引用。

### 32. CMS / G1 / ZGC 怎么选？⭐⭐⭐
💡 CMS 并发标记清除、已移除；G1 逻辑分代物理 Region、停顿可预测（-XX:MaxGCPauseMillis）；ZGC 着色指针+读屏障、**亚毫秒停顿与堆大小无关**。
📖 默认：JDK8 Parallel → 9+ G1 → 21 分代 ZGC（大堆低延迟首选）。

### 33. Minor GC 和 Full GC 触发条件？
💡 Minor：Eden 满；Full：老年代满、元空间满、空间分配担保失败、System.gc()。
📖 Full GC 频繁先看 GC 日志：回收效果差→内存泄漏或缓存滥用；回收有效→容量不足调参。

### 34. 内存泄漏怎么排查？
💡 jmap -dump 导出快照 → MAT 看支配树找可疑大对象；常见元凶：静态集合、ThreadLocal 未 remove、未关闭资源、监听器未注销。
📖 症状：老年代锯齿持续抬升、Full GC 后不回落。

### 35. 线上 CPU 100% 怎么排查？⭐⭐⭐
💡 top 定位进程 → `top -Hp pid` 定位线程 → 线程 id 转十六进制 → jstack 找到对应栈；Arthas 一条龙 `thread -n 3`。
📖 常见元凶：死循环、正则回溯、频繁 Full GC（GC 线程忙）、序列化死磕。

### 36. 类加载过程和双亲委派？
💡 加载→验证→准备→解析→初始化；收到加载请求先层层委托给父加载器，父无法处理才自己加载。
📖 意义：防核心类被篡改 + 同一类只加载一次；打破方式：重写 loadClass、线程上下文类加载器（JDBC SPI）、OSGi。

# 四、Spring 生态（10 题）

### 37. 谈谈 IOC 和 AOP？
💡 IOC：对象创建与依赖管理交给容器，DI 是其实现方式；AOP：把事务、日志等横切逻辑以动态代理织入，业务代码零侵入。
📖 AOP 底层：有接口默认 JDK 动态代理，无接口 CGLIB；SpringBoot 2+ 默认统一 CGLIB。

### 38. Bean 的生命周期？⭐⭐⭐
💡 实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → 初始化（InitializingBean/init-method）→ 后置处理（**AOP 代理在这里生成**）→ 使用 → 销毁回调。
📖 一句话记：造、注、初始化、销毁，扩展点都在前后做文章。

### 39. 三级缓存怎么解决循环依赖？⭐⭐⭐
💡 一级放成品、二级放半成品、三级放 ObjectFactory 工厂；B 依赖 A 时通过工厂提前拿到 A 的早期引用（或代理）。
📖 第三级存在的意义：延迟决定要不要提前生成 AOP 代理；构造器注入和多例的循环依赖无解。

### 40. Spring 事务什么时候失效？⭐⭐⭐
💡 private/static/final 方法、**同类自调用**（this 不走代理）、异常被 catch 吞掉、受检异常没配 rollbackFor、多线程调用、引擎不支持事务。
📖 根因高度统一：事务靠代理拦截 + 异常回滚检测，绕过任何一个环节就失效。

### 41. @Transactional 底层原理？
💡 AOP 环绕通知：获取连接关自动提交 → 执行业务 → 无异常提交/有异常回滚；连接与事务信息通过 ThreadLocal 绑定。
📖 传播行为控制事务边界，默认 REQUIRED（有就加入没有就新建）。

### 42. SpringBoot 自动装配原理？⭐⭐⭐
💡 @EnableAutoConfiguration → AutoConfigurationImportSelector 读取 `META-INF/spring/...AutoConfiguration.imports`（3.x 路径）加载候选配置类 → @ConditionalOnXxx 条件注解筛选生效。
📖 一句话：约定位置的配置清单 + 条件注解按需装配；自定义 Starter 就是照这套约定发布。

### 43. @Autowired 和 @Resource 区别？
💡 @Autowired 是 Spring 的，先 byType，多个候选再 byName；@Resource 是 JDK 标准注解（JSR-250），先 byName 找不到再 byType。
📖 多实现冲突：@Qualifier 指名道姓，或 @Primary 标默认。

### 44. BeanFactory 和 FactoryBean？⭐⭐
💡 BeanFactory 是 IoC 容器顶层接口（ApplicationContext 的爹）；FactoryBean 是能定制生产逻辑的特殊 Bean，getObject() 返回真正注册进容器的对象。
📖 getBean("xx") 拿产品、getBean("&xx") 拿工厂本身；MyBatis SqlSessionFactoryBean 是教科书案例。

### 45. SpringMVC 一次请求的流程？
💡 DispatcherServlet 接收 → HandlerMapping 找到 Handler → HandlerAdapter 执行（前置拦截器）→ Controller → 返回 ModelAndView → ViewResolver 解析渲染；@ResponseBody 直接走 HttpMessageConverter 序列化 JSON。
📖 全局异常处理：@RestControllerAdvice + @ExceptionHandler 统一兜底。

### 46. Spring 事件机制怎么用？
💡 发布 ApplicationEvent → @EventListener 监听，默认同步执行（同线程同事务），@Async 切异步。
📖 高频坑：事件里改库想跟随事务 → 用 @TransactionalEventListener(phase = AFTER_COMMIT)，避免事务未提交被读到。

# 五、AI 工程化（26 题 · AI 岗核心战场）⭐⭐⭐

### 47. RAG 的完整链路？
💡 离线：文档解析 → 切片 → Embedding → 存向量库；在线：query（改写）→ 检索 → Rerank → 拼 Prompt → LLM 生成 → 引用溯源。
📖 本质是给模型"开卷考试"，用检索外挂企业私有知识，解决幻觉和知识时效。

### 48. 为什么选 RAG 而不是微调？⭐⭐⭐
💡 知识频繁更新/需要溯源/数据敏感不能训练/预算有限 → RAG；要改变风格、输出格式、领域语感 → 微调；两者可叠加。
📖 一句话：**微调调性格，RAG 补教材**。

### 49. Embedding 是什么？
💡 把文本映射为高维稠密向量，语义相近 → 向量距离近；常见维度 768/1024/1536/3072。
📖 检索质量 = 切片质量 × Embedding 模型质量；选型看榜单（MTEB）+ 实测自己语料，中文注意选中文优化模型。

### 50. 相似度计算：余弦、内积、欧氏怎么选？
💡 检索普遍用**余弦相似度**（只看方向不看长度）；向量归一化后内积=余弦；欧氏距离对绝对数值敏感，聚类用得多。
📖 建库时 metric 参数要与 Embedding 模型的推荐配置对齐，别混用。

### 51. 分块（Chunking）策略怎么做？⭐⭐
💡 常见：固定长度、按标题/段落（保结构）、递归字符切分（LangChain 默认）、语义分块；经验值 256~512 token + 10%~20% 重叠。
📖 块太大→检索稀释，块太小→上下文碎片化；结构化文档（手册/FAQ）优先按标题层级切。

### 52. 为什么要混合检索？⭐⭐
💡 向量擅长**语义泛化**（"电脑"≈"计算机"），BM25/关键词擅长**精确命中**（型号、专名、错误码）；两路召回用 RRF（倒数排名融合）合并互补。
📖 生产 RAG 标配三件套：向量检索 + 关键词检索 + Rerank。

### 53. Rerank 是什么，为什么有效？
💡 用交叉编码器（Cross-Encoder）对 query-doc **逐对联合编码**精细打分、重排序，只取 top-k 进 Prompt。
📖 两阶段思想：召回（ANN，快而糙）→ 重排（交叉编码，慢而精）；牺牲一点延迟换相关性大幅提升。

### 54. 大模型幻觉怎么治理？⭐⭐⭐
💡 Prompt 约束（"仅根据以下资料回答，资料没有就说不知道"）+ RAG 供证据 + 引用溯源 + 低温度 + 输出后校验（关键词/规则/NLI）+ 人工兜底通道。
📖 目标不是消灭幻觉（做不到），而是**可控 + 可发现 + 可兜底**。

### 55. Function Calling 的原理？⭐⭐⭐
💡 开发者声明工具 schema → 模型判断需要调哪个工具，输出**结构化参数（它自己不执行！）** → 应用执行工具 → 结果回传 → 模型生成最终回答。
📖 金句：模型是大脑，执行永远在你的代码里——所以权限、超时、重试都由你掌控。

### 56. MCP 是什么？⭐⭐⭐（2026 爆火）
💡 Model Context Protocol：AI 应用接入外部工具/数据源的**开放标准协议**，相当于"AI 的 USB 口"；角色分 Host/Client/Server，能力分 tools/resources/prompts。
📖 价值：工具一次封装、处处接入，告别每个应用重复写适配。

### 57. Function Calling 和 MCP 什么关系？
💡 FC 是**模型的能力**（会不会调工具、怎么给参数）；MCP 是**工具的接入协议**（工具怎么标准化地暴露给各类 Host）。
📖 MCP Server 描述的能力，最终仍通过 function calling 机制被模型使用——插座与插头的关系。

### 58. Spring AI 的核心组件？⭐⭐⭐
💡 ChatClient（Fluent 对话入口）、ChatModel（模型抽象）、EmbeddingModel、VectorStore（向量库统一接口）、Advisor（拦截器链：记忆/RAG/日志）、StructuredOutputConverter（结构化输出）。
📖 最大价值是抽象层：换模型只改 starter 依赖和配置，业务代码不动。

### 59. Spring AI 和 LangChain4j 怎么选？
💡 Spring AI：Spring 官方血缘、Advisor 生态、纯 Spring 栈团队无缝；LangChain4j：组件更全（文档加载器/记忆策略丰富）、AiServices 注解式接口优雅，也能与 Spring 集成。
📖 答题姿势：没有银弹，按团队技术栈和生态熟悉度选型，两者底层概念（Model/VectorStore/Memory）相通。

### 60. 用 Spring AI 快速实现 RAG？
💡 文档 → TokenSplitter 切片 → EmbeddingModel 向量化 → VectorStore 存（PGVector/Redis/Milvus 等）；查询侧把 QuestionAnswerAdvisor 挂到 ChatClient，自动"检索→拼 Prompt"。
📖 Advisor 链还可叠加记忆、日志、敏感词等横切能力，是 Spring AI 的设计精髓。

### 61. 流式输出怎么实现？⭐⭐⭐
💡 模型 API 返回 SSE 流（增量 chunk）→ 后端 WebFlux 返回 `Flux<ChatResponse>`（或 MVC 用 SseEmitter）逐块推送 → 前端 EventSource/fetch ReadableStream 逐字渲染。
📖 为什么流式：首 token 时间决定体感，等待 5s 出整段 vs 1s 开始逐字出，后者体验碾压；注意用户"停止生成"要能中断上游。

### 62. Token 是什么？怎么控制成本？⭐⭐⭐
💡 模型处理文本的最小单位，中文大致 1 字 ≈ 1~2 token（随分词器而异）；成本 = (输入 + 输出 token) × 单价，输入便宜输出贵。
📖 控本组合拳：Prompt 精简、检索 top-k 限制、相同前缀缓存（Prompt Caching）、大任务路由小模型、限制 max_tokens、非实时任务走批处理。

### 63. 上下文窗口超限怎么办？
💡 滑动窗口截断旧对话、历史摘要压缩、长期记忆外挂（向量库检索）、关键信息放在开头和结尾。
📖 "Lost in the Middle"现象：长上下文中间部分召回率显著下降——重要内容别埋中间。

### 64. 多轮对话记忆怎么实现？⭐⭐
💡 方案：最近 N 轮窗口、按 token 预算动态截断、摘要记忆（旧对话压缩成一段）、向量记忆（语义检索相关历史）；框架：Spring AI ChatMemory、LangChain4j ChatMemoryStore。
📖 生产落地：Redis 存 + 会话 ID 隔离 + 过期策略，重要用户画像单独结构化存储。

### 65. temperature 和 top_p 是干嘛的？
💡 temperature 控制采样随机性：低（0~0.3）稳定适合知识问答/抽取，高（0.8+）发散适合创意；top_p 核采样只从累积概率前 p 的候选里挑。一般二选一调，不叠加。
📖 企业 RAG 场景默认低温度，客服闲聊可适当调高。

### 66. 怎么保证模型输出稳定的 JSON？⭐⭐
💡 三层保险：模型侧开 JSON mode/指定 response_format；框架侧用结构化输出转换器（Spring AI BeanOutputConverter 自动生成 schema 并解析校验）；工程侧解析失败自动重试 + 正则兜底。
📖 结构化输出是工具调用、下游解析、自动化流水线的地基，不稳定一切白搭。

### 67. RAG 效果怎么评估？⭐⭐
💡 检索层：召回率、MRR、nDCG；生成层：忠实度（答案是否忠于检索内容）、相关性、正确性——用 LLM 当裁判（Ragas 思路）；在线指标：采纳率、人工纠错率。
📖 没有评估集的 RAG 调优都是盲调——先攒 100 条标注 QA 再谈优化。

### 68. 什么是 Agent？ReAct 是什么？⭐⭐⭐
💡 Agent = LLM（大脑）+ 工具 + 记忆 + 规划的自主执行体；ReAct = Reason（想）+ Act（调工具）交替循环，直到认为任务完成。
📖 落地三大难点：任务拆解的可靠性、出错后的恢复策略、多轮调用的成本与延迟控制。

### 69. 大模型 API 不稳定怎么治理？⭐⭐
💡 超时 + 指数退避重试、多模型热备自动切换（主模型超时/限流切备用）、降级链（大模型→小模型→规则/缓存答案）、按 key 限流排队、全链路 trace 观测。
📖 工程化姿势：自建统一 AI 网关层收口（路由/密钥/计费/审计），业务方不直连厂商 SDK。

### 70. Prompt 注入攻击怎么防？⭐⭐（安全必考）
💡 输入侧：系统指令与用户输入严格隔离（分隔符+角色标记）、敏感指令检测；输出侧：检测是否泄露系统提示词；工具侧：白名单 + 最小权限 + 高危操作人工确认。
📖 进阶认知：RAG 检索回来的文档本身可能是攻击载体（**间接注入**），检索内容同样不可信。

### 71. 知识库怎么保持更新？⭐⭐
💡 增量同步：监听文档变更（hash/mtime 比对）→ 重新切片+向量化 → 按 doc_id 先删后插；辅以定期全量对账任务。
📖 一致性比实时更重要：多数企业知识库 T+1 或小时级定时同步即可。

### 72. 你项目里的大模型接口层怎么设计？⭐⭐⭐（开放架构题）
💡 统一 AI 网关：模型路由（按任务/成本分流）、密钥管理、限流熔断、审计日志；业务侧只依赖 ChatModel 抽象；SSE 透传 + 支持用户中断；异步任务走 MQ 削峰。
📖 面试官想听的不是"我会调 API"，而是**把 LM 当不稳定第三方依赖来做工程治理**。
